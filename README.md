# Obsidian Shrine

Технодемо souls-like RPG на Unreal Engine 5 (C++).

## Первый запуск на Windows

1. Установить через Epic Games Launcher **Unreal Engine 5.7** (или поправить `EngineAssociation` в
   `ObsidianShrine.uproject` под установленную версию).
2. Установить **Visual Studio 2022** с workload «Game development with C++» (MSVC, Windows SDK) — Unreal подскажет
   точные версии, если чего-то не хватит.
3. Установить **Git LFS**: `git lfs install`.
4. Клонировать репозиторий и в корне выполнить:

```powershell
powershell -ExecutionPolicy Bypass -File .\Scripts\Verify.ps1
```

Скрипт проверяет манифесты, собирает проект, генерирует уровни и прогоняет автотесты. Итог —
`Saved\Reports\summary.md`.

Проще всего попросить Claude Code на Windows: «спуллить, прогнать Verify.ps1 и починить, что сломалось».

## Что внутри

| Путь | Что |
|---|---|
| `Source/ObsidianShrine` | C++ код игры |
| `Source/ObsidianShrine/Private/Tests` | Автотесты |
| `Game` | Манифесты игры в YAML: действия, оружие, персонажи, ИИ, уровни, настройки, управление, тексты |
| `Tools` | Компилятор манифестов и его тесты (обычный Python, Unreal не нужен) |
| `Content/Data`, `Content/LevelData` | Данные, собранные из манифестов; руками не правятся |
| `Docs` | Справочник полей, роадмап, список непроверенного |
| `Content/Python` | Пайплайн контента: уровни и ассеты создаются скриптами |
| `Scripts/*.ps1` | Сборка, контент, тесты для Windows |
| `Config` | Настройки движка и проекта |

## Управление

Раскладка задаётся в `Game/input.yaml`; ниже — та, что там сейчас.

| Действие | Клавиатура / мышь | Геймпад |
|---|---|---|
| Движение / камера | WASD / мышь | левый / правый стик |
| Лёгкая атака (комбо из трёх) | ЛКМ | RB |
| Тяжёлая атака | F | RT |
| Блок (нажать прямо перед ударом — идеальный блок) | ПКМ (держать) | LB (держать) |
| Уклонение | Пробел | B (коротко) |
| Бег | Shift (держать) | B (держать) |
| Захват цели / сменить цель | Q или СКМ / колесо мыши | R3 / крестовина влево-вправо |
| Взаимодействие (святилище, потерянные осколки, выход на другую карту) | E | A |

Консоль: `os.DebugCombat 1` — показать зоны поражения, `os.ResetSave` — стереть прогресс,
`os.ReloadData` — перечитать данные, не перезапуская игру (см. ниже).

Карты: из песочницы в Пепельный склеп ведут ворота у северного края арены (серая плита). Они запечатаны, пока
не побеждён Страж святилища. Игра продолжается с сейва: при запуске со стартовой карты она сама открывает карту
последнего святилища; смерть возвращает к последнему святилищу, даже если оно на другой карте. Открытая напрямую
карта (в редакторе или командой `open`) играется как есть.

Пока ассеты не импортированы, персонажи — цветные цилиндры: синий игрок, красные враги, фиолетовый босс.
«Нос» показывает, куда смотрит персонаж; планка-оружие поднимается на замахе, ложится вперёд на длину реальной
зоны удара в момент попадания и держится поперёк груди в блоке. Белеет персонаж в кадрах неуязвимости.

## Ассеты с Fab

Наборы импортируются на Windows в `Content/ThirdParty/<Набор>` и в git не попадают. Сейчас нужны два бесплатных
набора Epic: **Paragon: Greystone** (игрок) и **Paragon: Minions** (обычный враг).

1. На Fab добавить оба набора в библиотеку и через Epic Games Launcher (или плагин Fab в редакторе) добавить их в
   проект. Если лаунчер не предлагает версию 5.7 — добавить в пустой проект ближайшей версии и перенести через
   Migrate.
2. Переложить папки в `Content/ThirdParty`: `ParagonGreystone` и `ParagonMinions` (в редакторе — перетащить папку,
   затем Fix Up Redirectors на `Content`).
3. Прогнать `Verify.ps1`: конвейер контента запишет опись `Docs/ASSET_INVENTORY.md`. Её закоммитить — по ней
   заполняются `Game/assets.yaml` и наборы анимаций.

## Как добавлять контент

Игра описывается YAML-файлами в папке `Game`. Код для этого менять не нужно.

| Что добавить | Где |
|---|---|
| Атаку, уклонение, реакцию | `Game/data/*.yaml`, секция `Actions` |
| Оружие | `Game/data/*.yaml`, секция `Weapons` |
| Врага, босса | `Game/data/*.yaml`, секции `Characters` и `AIProfiles` |
| Уровень | `Game/levels/<имя>.yaml` |
| Переход между уровнями | `Exits` в обоих уровнях, каждый выход указывает `To` на выход другого |
| Набор освещения | `Game/lighting.yaml` |
| Модель, анимацию, звук, эффект из импортированного набора | имя в `Game/assets.yaml`, затем это имя в данных |
| Анимации персонажа | `Game/data/*.yaml`, секция `AnimationSets`, у персонажа — `AnimationSet` |
| Звуки, эффекты, тряску камеры, хит-стоп | `Game/data/cosmetics.yaml`, у персонажа — `Cosmetics` |

Настраивается там же:

| Что поменять | Где |
|---|---|
| Камеру, захват цели, отклик кнопок, правила смерти, стартовую карту | `Game/game.yaml` |
| Клавиши и кнопки геймпада | `Game/input.yaml` |
| Любую надпись на экране | `Game/texts.yaml` |

Все поля с типами, значениями по умолчанию и пояснениями — в [Docs/REFERENCE.md](Docs/REFERENCE.md).
Готовые примеры: враг `Game/data/enemy_husk.yaml`, босс с фазами `Game/data/boss_ashen_knight.yaml`,
уровень `Game/levels/ashen_crypt.yaml`.

После правки YAML:

```bash
python3 Tools/build_data.py
```

Скрипт проверяет все файлы и пересобирает данные для игры (`Content/Data`, `Content/LevelData`) и справочник.
Если что-то не так — опечатка в имени, ссылка на несуществующую атаку, окно удара за пределами действия,
цвет без кавычек — он ничего не пишет и показывает файл и строку:

```
Game/data/enemy_husk.yaml:33: AI profile 'husk_ai' uses action 'husk_slahs', which is not defined anywhere
```

Файлы в `Content/Data` и `Content/LevelData` руками не правятся: они создаются из YAML и коммитятся вместе с ним.
Стартовую карту скрипт сам переносит из `Game/game.yaml` в `Config/DefaultEngine.ini`.

### Правки на лету

Игру не обязательно перезапускать после каждой правки. Пока она запущена:

1. поправить YAML;
2. пересобрать данные: `.\Scripts\BuildData.ps1 -Write` (или `python3 Tools/build_data.py`);
3. в консоли игры (клавиша `~`) набрать `os.ReloadData`.

Новые числа, клавиши и тексты действуют сразу: враги и игрок получают новые характеристики, не теряя текущего
здоровья, действие, которое уже выполняется, доигрывается по-старому. Не подхватывается на лету только то, что
записано в сам уровень (расстановка, параметры святилищ) и стартовая карта — для них нужна пересборка контента
(`.\Scripts\BuildContent.ps1`).

План развития — в [Docs/ROADMAP.md](Docs/ROADMAP.md).
