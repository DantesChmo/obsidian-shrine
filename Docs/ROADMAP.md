# Роадмап: игра из манифестов

Статус: вторая редакция, после независимой критики; ждёт согласования. Ничего из описанного ещё не сделано.

## Цель

Всё, что игра уже умеет, описывается текстом в YAML: персонажи, атаки, оружие, ИИ, уровни, управление, настройки,
привязка ассетов и косметики. Программирование нужно только для новой механики — и каждая новая механика
пишется один раз, после чего тоже становится полем в манифесте.

Проверка цели: **второй уровень со вторым боссом описывается без единой строки C++ и Python.**
Описать его можно уже на этапе 1а; дойти до него в игре — после этапа 2 (переходы между картами).

## Исходная точка

Сделано (коммит `bf709c0`, около 3600 строк C++, ни разу не собиралось):

- действия, оружие, персонажи, ИИ — в `Content/Data/*.json`;
- бой, игрок, враги, босс с фазами, цикл смерти, сейв, HUD — в C++.

Что из существующего не в данных и что с этим делать:

## Сквозные решения

### Формат: YAML пишет человек, игра читает JSON

В Unreal нет чтения YAML. Библиотека YAML внутри C++ или собственный парсер на C++ — это чужой или новый код
вслепую, без машины для сборки. Поэтому:

- исходники — `Game/**/*.yaml`;
- скрипт `Tools/build_data.py` проверяет их и пишет `Content/Data/*.json`;
- **сгенерированный JSON коммитится.** Игра работает сразу после `git pull`, даже если скрипт никто не
  запускал; расхождение YAML и JSON ловит проверка «пересобрать и сравнить» в `Verify.ps1` и в тестах на Mac;
- скрипт пишется под Python 3.11 (такой идёт в поставке Unreal) и запускается и на Mac, и на Windows.

YAML читает библиотека **PyYAML**, положенная в репозиторий (чистый Python, лицензия MIT). Свой разбор
подмножества YAML хуже: незнакомая конструкция давала бы ошибку вместо работы. PyYAML — стороннее скачивание,
нужно ваше «да».

У YAML есть ловушки, компилятор обязан их закрыть:

- `PlaceholderColor: #7A3FB8` без кавычек — это комментарий, значение пропадёт. Пустое значение в строковом
  поле — ошибка с подсказкой «возьмите в кавычки»;
- `on`, `off`, `yes`, `no` превращаются в «истина / ложь» — в строковых полях это ошибка;
- ошибки сообщаются с файлом и номером строки.

### Схема берётся из кода, а не пишется отдельно

Первая редакция предлагала отдельный файл схемы. Это третий источник правды, который будет расходиться с
двумя другими. Вместо этого:

- имена, типы и значения по умолчанию скрипт читает прямо из `OSDataTypes.h` — заголовок написан единообразно,
  разбирается на Mac;
- описания полей — комментарии в том же заголовке; из них генерируется справочник `Docs/REFERENCE.md`;
- отдельно хранится только то, чего в заголовке нет: допустимые диапазоны.

Движок молча игнорирует незнакомые ключи, так что проверка в Python — единственная защита от опечаток в
названиях полей.

### Windows: что можно делать без неё и что нельзя

Нынешний C++ не собирался. Каждая новая строка C++ до первой сборки удорожает эту сборку.

- **Этапы 0 и 1а — без Windows.** Это Python и данные, C++ не трогается, результат проверяется на Mac тестами.
- **Этап 1б и дальше — после первой сборки.** Он меняет C++ примерно в восьми файлах (оценка рецензента:
  400–600 строк): перенос настроек камеры из конструктора, разбор названий клавиш, прокидывание `game.yaml`
  через компоненты.
- Всё непроверенное перечисляется в `Docs/UNVERIFIED.md` — это готовый план первой сессии на Windows.

Если после этапа 1а Windows всё ещё недоступна, это ваша развилка: ждать или писать 1б вслепую, понимая цену.

## Этапы

### Этап 0. Формат и инструменты — на Mac

- `Tools/build_data.py`: YAML → проверка → JSON; PyYAML в репозитории.
- Чтение полей из `OSDataTypes.h`, файл диапазонов, генерация `Docs/REFERENCE.md`.
- Перевод четырёх существующих JSON в YAML.
- Тесты компилятора (`python3 -m unittest`).
- Подключение к `Verify.ps1`: пересборка данных и проверка, что закоммиченный JSON не устарел.

Готово, когда на Mac проходят тесты, в которых:

1. опечатка в id атаки, незнакомое поле и цвет без кавычек дают ошибку с файлом и строкой;
2. JSON, собранный из новых YAML, по смыслу совпадает с нынешним.

### Этап 1а. Уровни из манифестов — на Mac

- `Game/levels/*.yaml`. В манифесте: путь карты, название пресета освещения, блоки в сантиметрах, меши по
  логическим именам, старт игрока, враги (персонаж, постоянный id), святилища.
  Не будет: произвольных классов и свойств, параметров отдельных ламп, циклов, наследования, префабов —
  иначе манифест превратится в самодельный редактор.
- Сборщик из двух частей: **расчёт** (манифест → плоский список «что и где поставить», чистый Python,
  тестируется на Mac) и тонкое **применение** в редакторе Unreal.
- `sandbox_level.py` остаётся, пока применение хотя бы раз не отработало на Windows.
- Проверки на Mac: враг ссылается на существующего персонажа; id святилищ и постоянные id боссов уникальны
  во всей игре (сейчас это не проверяет никто).
- Второй уровень и второй босс, описанные только в YAML.

Готово, когда на Mac проходят тесты, в которых:

1. расчёт по `levels/sandbox.yaml` даёт тот же список объектов, что ставит нынешний скрипт;
2. `levels/second.yaml` и второй босс проходят все проверки без правок в C++ и Python.

### — Контрольная точка: Windows —

- `Verify.ps1`, починка сборки и тестов, первая игра руками.
- Первый запуск применения манифеста уровня; удаление `sandbox_level.py`.
- **Пробная упаковка игры.** Пути к ассетам в данных — это строки, сборщик релиза их не видит и может не
  положить в игру ни ассеты, ни вторую карту. Лучше узнать это сейчас, чем на последнем этапе.

### Этап 1б. Настройки, управление, тексты

- `Game/game.yaml`, `Game/input.yaml`, таблица текстов — всё из колонки «этап 1б» таблицы выше.
- Перезагрузка данных на лету (`os.ReloadData`): сейчас персонажи копируют определения при появлении, поэтому
  нужна ещё и повторная раздача данных живым персонажам.

Готово, когда: поиск по исходникам не находит игровых чисел, клавиш и текстов вне списка «остаётся в коде
намеренно»; смена клавиши и текста подсказки в YAML видна в игре.

### Этап 2. Несколько карт

- Переход между картами и сохранение состояния по каждой карте.

Готово, когда: из песочницы можно дойти до второго уровня из этапа 1а, убить второго босса, выйти и
продолжить с сейва.

### Этап 3. Привязка ассетов и косметики

- `Game/assets.yaml`: логическое имя → путь ассета. Из него же скрипт формирует список того, что класть в
  релиз.
- Наборы анимаций на персонажа. Здесь принимается решение про Animation Blueprint (единственное разрешённое
  исключение из правила «без блюпринтов»).
- Таблица косметики: событие (удар попал, блок, идеальный блок, шаг, уклонение, смерть, фаза босса) → звук,
  частицы, тряска камеры, хит-стоп.

Готово, когда: один названный бесплатный набор с Fab подключён к игроку и одному врагу правкой только YAML.
Набор выбираем вместе в начале этапа.

### Этап 4. Недостающие механики

Каждая — код один раз, потом манифест.

- Объекты мира: двери, рычаги, срезы, туманные врата арены, триггеры.
- Фляга лечения и подбираемые предметы.
- Прокачка у святилища: кривые роста статов и цен.
- Смена оружия.
- Интерфейс: главное меню, пауза, экран святилища.

Предлагаю для технодемо не делать: переназначение клавиш в игре, экран настроек, требования по статам к
оружию, инвентарь сверх фляги.

Готово, когда: проходится цепочка «меню → уровень → прокачка у святилища → босс → следующая карта».

### Этап 5. Расширение ИИ и боя

По мере того как этого требуют конкретные враги: обход препятствий, дальние атаки и снаряды, патруль, зрение,
новые формы ударов, зона удара по мешу оружия. Каждое поле появляется вместе с кодом, который его исполняет.

Предлагаю не делать: слух и групповое поведение.

Готово, когда: есть враг дальнего боя и враг с патрулём, описанные только в YAML.

### Этап 6. Выпуск

Скрипт упаковки под Win64, настройки графики, проверка производительности.

Готово, когда: упакованная игра проходится от меню до последнего босса на чистой машине.

## Что изменилось после критики

| Было в первой редакции | Стало | Почему |
|---|---|---|
| Этап 1 целиком до Windows, «изменения C++ небольшие» | Разбит на 1а (без C++) и 1б (после сборки) | 1б — это сотни строк C++ поверх несобранных |
| Сгенерированный JSON не в git | Коммитится | иначе свежий `git pull` даёт игру без данных, а старые и новые файлы конфликтуют |
| Отдельный файл схемы | Схема читается из заголовка C++ | меньше источников правды |
| Упаковка — последний этап | Пробная упаковка в первой точке Windows | пути-строки могут не попасть в релиз |
| Поле формы удара с одним вариантом | Убрано до этапа 5 | поле без кода, который его исполняет |
| Перезагрузка данных на этапе 1 | Этап 1б, с раздачей живым персонажам | без раздачи перезагрузка ничего не меняет |
| Тексты HUD отдельно от таблицы текстов | Одна работа на этапе 1б | это одно и то же |
| Цель «второй уровень без кода» не привязана к этапу | Описание — критерий этапа 1а, прохождение — этапа 2 | цель должна где-то проверяться |
| Таблица «что не в данных» из 7 строк | Расширена, добавлен список «остаётся в коде» | иначе критерий «в C++ нет игровых чисел» недостижим |
